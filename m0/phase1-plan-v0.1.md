# 第一阶段开发计划：Lauren 核心链路个人精简版

版本：0.1  
交付对象：Grok Bot 指挥官及开发团队  
首发平台：macOS、Windows、Linux  
批准：2026-11-04 陛下批（正文即原 V1.1，仅改版本号）

本阶段以 **1 个幕僚长 + 1 个开发助手 + 1 个验证助手**，复现 Lauren 团队图中的核心工程闭环。

用户安装 OpenMausBot，按照 GitHub 文档导入团队，完成模型引擎、工作目录和必要权限的一次性配置，即可运行 Demo，看到任务分派、开发、独立验证、失败修复、条件合并与经验复用的完整过程。

以下是实施与验收要求。具体接口、导入能力和平台兼容性必须实测，不得将角色提示词或上游文档描述视为已完成的系统功能。

## 一、一期目标与核心链路

```text
用户提出需求
    ↓
幕僚长明确范围、拆解任务、冻结验收标准
    ↓
开发助手在独立工作区修改代码并自检
    ↓
验证助手检查准确版本，运行应用并保存证据
    ├─ 通过 → 检查合并条件 → 合并到 Demo 集成分支 → 汇报
    └─ 失败 → 返回开发助手修复 → 再次验证

失败中出现可复用教训
    ↓
形成候选规则、预检或回归测试
    ↓
验证能够捕获问题，且不误伤正常情况
    ↓
保存版本，供后续相关任务加载
```

一期必须闭合三个环：

1. **执行闭环**：需求转化为代码产物，并经过独立验证。
2. **交付闭环**：通过验证的准确版本完成合并，留下可追溯记录。
3. **改进闭环**：失败经验形成有效检查，在后续任务中发挥作用。

失败记录必须保存，但不要求每次失败都生成新规则。

| 平台 | 一期首发基线 | 要求 |

| macOS | Apple 芯片，明确支持的系统版本 | 原生运行、完整 Demo |

## 三、角色职责（一期仅此三角色；不加 Nancy / Matcha）

### 1. 幕僚长
负责：理解需求；明确目标/范围/非目标/完成条件；判断是否进开发；拆最小可验证任务；传递必要背景；按结构化结果推进状态；汇总产物/证据/用量/阻塞；条件满足时请求程序执行合并。
约束：开发任务默认交给开发助手；不以开发者声明代替验证；不自行覆盖失败、提高预算或扩大范围；不凭模型判断跳过合并条件。简单问答可直办。

### 2. 开发助手
负责：读相关代码与已发布规则；在指定工作区修改；自检；提交准确版本/变更摘要/自检记录；按验证问题修复；提出规则或回归测试建议。
约束：不擅自扩大需求；不直接合并集成分支；不将自检当独立验收；不通过降低验收标准过关。

### 3. 验证助手
负责：读原始需求/验收标准/待验收版本；实际执行检查并跑应用；保存命令/退出码/日志/必要截图；返回通过/不通过/无法判定；验证候选规则有效性。
约束：默认不改待验收代码；不直接采信开发助手成功声明；无法执行的检查如实说明；报告绑定准确版本及环境。

## 四、状态机

主路径：`待执行 → 执行中 → 待验证 → 验证通过 → 待合并 → 已完成`

补充：`需修改`（检查完成但不符合）· `受阻`（环境/权限/依赖/预算）· `已取消` · `合并失败`

验证通过 ≠ 任务完成；须交付条件满足后才完成。

## 五、M0 必做（先于此再 M1+）

三平台分别确认安装认证、三角色导入、委派、结果读取、工作目录访问、准确版本验证、重启后记录、团队包可携带内容、pstack 复用与许可证。

M0 交付：三平台兼容表、每平台最小运行证据、导入清单、pstack 说明、接口与本地适配方案、缺口与排期。

## 六、Demo 场景（跨平台同一套）

| 场景 | 操作 | 必须看到 |
|---|---|---|
| 功能开发 | 增加任务筛选 | 分派→实现→验证→合并→报告 |
| 失败返工 | 预置缺陷待验收 | 失败→修复→再验通过 |
| 经验复用 | 注入同类问题 | 新检查拦截 |
| 环境受阻 | 缺依赖/不可写 | 受阻与恢复说明 |
| 中断恢复 | 中断执行或验证 | 可恢复不重复写 |
| 合并拦截 | 验后改代码或基线 | 拒绝过期验收 |
| 路径兼容 | 中文与空格路径 | 正常 |
| 进程清理 | 中断 Demo 服务 | 能辨认并清理 |

## 七、合并

仅 Demo **本地** Git 集成分支。用户可选：条件满足后自动合并，或验证通过后确认合并。合并须核对提交与验证报告一致、检查全过、无冲突、基线未脏。
