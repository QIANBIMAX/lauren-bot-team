## 0. 硬约束（对齐批件）

1. OpenMausBot（OMB）= **队工作台平台**，只当平台、**不 fork**；工程闭环逻辑放自研 `lauren-team-kit`。【文档依据】
2. 一期三角色仅：**幕僚长 / 开发助手 / 验证助手**。【文档依据：批件 §三；ROLE-RULING】
3. 主状态：`待执行 → 执行中 → 待验证 → 验证通过 → 待合并 → 已完成`；补充：`需修改` / `受阻` / `已取消` / `合并失败`。【文档依据：批件 §四】
4. Demo：跨平台小型**任务列表**应用；场景含筛选、预置缺陷返工、经验复用、受阻、中断恢复、合并拦截、中文空格路径、进程清理。【文档依据：批件 §六】
5. 合并：仅 Demo **本地**集成分支；策略 `confirm`（建议默认）或 `auto`。【文档依据：批件 §七】
6. 验收：未执行检查不得标通过；三平台均须真实验证；M0 先于实现。【文档依据：批件 §五】
7. 硬边界：无真实 Slack/企微全量；不碰生产权限；不自动合公司主仓。【文档依据：主稿硬边界 + 批件外部服务表】

## B. 三角色任务协议

### B.1 角色职责（批件摘要）

| 角色 | 负责 | 约束 |
|---|---|---|
| 幕僚长 | 明确范围/非目标/验收；拆最小可验证任务；推进状态；汇总产物/证据/阻塞；条件满足时请求程序合并 | 不代替验证；不擅自扩大范围/预算；不凭模型跳过合并条件 |
| 开发助手 | 读代码与已发布规则；在指定工作区修改；自检；提交准确版本与摘要；按验证问题修复；提出规则/回归建议 | 不直接合集成分支；自检≠独立验收；不降验收标准 |
| 验证助手 | 读需求/验收/待验版本；**实际执行**检查并跑应用；保存命令/退出码/日志/截图；返回通过/不通过/无法判定；验证候选规则 | 默认不改待验代码；不采信开发自述成功；报告绑定准确版本与环境 |

### B.2 状态枚举

**主路径**：`待执行` → `执行中` → `待验证` → `验证通过` → `待合并` → `已完成`

**补充**：`需修改` · `受阻` · `已取消` · `合并失败`

> 验证通过 ≠ 任务完成；须交付/合并条件满足后才 `已完成`。【文档依据：批件 §四】

### B.3 状态转移条件

```text
[新建] --幕僚长签发协议--> 待执行
待执行 --开发助手开工(worktree/分支就绪)--> 执行中
执行中 --开发提交待验版本+自检记录--> 待验证
执行中 --环境/权限/依赖/预算不可继续--> 受阻
执行中 --用户或幕僚长取消--> 已取消
待验证 --验证助手跑完全部必做检查且通过--> 验证通过
待验证 --检查完成但不符合验收--> 需修改
待验证 --无法执行检查(环境等)--> 受阻 或 结果=无法判定(仍停待验证/受阻，不得标通过)
需修改 --开发修复并重新提交版本--> 待验证
验证通过 --合并前置核对通过，进入合并队列--> 待合并
验证通过 --发现验收绑定版本被改/基线脏（合并拦截）--> 需修改 或 保持验证通过但拒绝合并（记合并拦截事件）
待合并 --本地集成分支合并成功--> 已完成
待合并 --冲突/检查失败/版本不一致--> 合并失败
合并失败 --修复后重走验证或重试合并--> 待验证 或 待合并
受阻 --阻塞解除--> 待执行 或 执行中 或 待验证（按恢复点）
任意非终态 --取消--> 已取消
```

**硬规则**：任一必做检查未执行 ⇒ 禁止写入 `验证通过`。【文档依据：批件 §五/角色】【需开发：kit 校验】

### B.4 任务协议字段表

| 字段 | 类型 | 谁写 | 必填 | 说明 |
|---|---|---|---|---|
| `schema_version` | string | 幕僚长 | 是 | 如 `lauren-task-protocol/0.1` |
| `task_id` | string | 幕僚长 | 是 | 唯一 id，全流程不变 |
| `title` | string | 幕僚长 | 是 | 短标题 |
| `status` | enum | 当前责任角色 | 是 | 见 B.2 |
| `created_at` / `updated_at` | string (ISO8601) | 系统/责任角色 | 是 | 建议存 Asia/Shanghai 偏移 |
| `requester` | string | 幕僚长 | 是 | 用户或发起方 |
| `roles.chief` / `developer` / `verifier` | string | 幕僚长 | 是 | OMB bot 显示名或 id |
| `scope.goal` | string | 幕僚长 | 是 | 目标 |
| `scope.in_scope` / `out_of_scope` | string[] | 幕僚长 | 是 | 范围/非目标 |
| `acceptance[]` | object | 幕僚长签发；验证助手执行 | 是 | 每条含 `id`,`description`,`command`,`must_run`,`pass_criteria` |
| `acceptance[].must_run` | bool | 幕僚长 | 是 | true 则未跑不得 Pass |
| `worktree.path` | string | 幕僚长/开发 | 是 | 独立工作区路径 |
| `worktree.branch` | string | 开发 | 是 | 任务分支 |
| `integration.branch` | string | 幕僚长 | 是 | Demo 本地集成分支名，如 `demo/integration` |
| `merge_policy.mode` | `confirm`\|`auto` | 幕僚长 | 是 | 建议默认 `confirm` |
| `artifact.commit` | string | 开发 | 待验后是 | 待验收精确 commit |
| `artifact.summary` | string | 开发 | 是 | 变更摘要 |
| `artifact.self_check` | object | 开发 | 是 | 自检命令与结果（不得替代验收） |
| `verification.ran_at` | string | 验证 | 验后是 | |
| `verification.result` | `pass`\|`fail`\|`inconclusive` | 验证 | 验后是 | inconclusive 不得升 `验证通过` |
| `verification.checks[]` | object | 验证 | 验后是 | `acceptance_id`,`executed`,`exit_code`,`log_path`,`screenshot_paths` |
| `verification.bound_commit` | string | 验证 | 验后是 | 必须等于 `artifact.commit` |
| `evidence_dir` | string | 验证/kit | 是 | 相对 `workspace/runs/<task_id>/` |
| `blockers[]` | object | 任一 | 否 | 受阻原因与恢复建议 |
| `lessons.candidates[]` | object | 开发建议；验证确认 | 否 | 候选规则/预检/回归；确认前不生效 |
| `lessons.published[]` | object | 验证通过有效性后幕僚长/kit | 否 | 已发布供后续加载 |
| `merge.attempted_at` / `merge.result` / `merge.notes` | mixed | 幕僚长触发程序 | 否 | 合并结果 |
| `history[]` | object | kit | 是 | `{at,actor,from,to,note}` 状态审计 |

完整 JSON Schema 见同目录 `M0-任务协议.schema.json`。【需开发：运行时校验】

### B.6 与 Demo 场景对齐

| 场景 | 协议如何体现 |
|---|---|
| 筛选功能 | 幕僚长写 acceptance 含筛选命令/UI 检查；主路径走到已完成 |

| 进程清理 | 验证助手/脚本记录 PID；中断后可辨认清理 |

## C. Demo 功能切片 + 验收命令草案

Demo 应用：跨平台小型任务列表（建议路径 `demo-app/`，本地 Git，集成分支 `demo/integration`）。

### 切片 C1：任务筛选功能（主路径）

| 项 | 内容 |
|---|---|
| 目标 | 增加按状态/关键词筛选任务；合并进 Demo 集成分支并出报告 |
| 预置缺陷 | 无（干净基线） |
| 验收命令草案 | 见下 |
| Pass/Fail | 全部 must_run 检查 exit 0 且断言命中；任一条未执行⇒不得 Pass |
| 经验回流落点 | 一般不回流；若失败则 `lauren-team-kit/skills/generated/` 与 `rules/` |

```bash
# 假设 demo-app 提供 CLI；具体入口【需开发】
export DEMO_ROOT="workspace/repos/demo-app"
cd "$DEMO_ROOT"
python -m demo_app.seed --fixture fixtures/basic.json
python -m demo_app.filter --status open --query "发票" > /tmp/filter.out
grep -q "发票" /tmp/filter.out
python -m demo_app.filter --status done | grep -v "open-only-task" >/dev/null
```

标签：【需开发】命令与模块名以实现为准；【需实测】三平台。

### 切片 C2：预置缺陷返工

| 项 | 内容 |
|---|---|
| 目标 | 待验版本故意缺筛选边界（如空关键词抛异常）；验证失败→修复→再验通过 |
| 预置缺陷 | `filter("")` 抛未捕获异常或返回 500 |
| 验收命令草案 | |
| Pass/Fail | 第一轮必须 fail；修复后第二轮 pass；evidence 保留两轮 report |
| 经验回流落点 | `demo-app/tests/test_filter_empty_query.py`；`lauren-team-kit/rules/filter-empty-query.md` |

```bash
python -m demo_app.filter --query "" ; test $? -eq 0   # 期望修复后成功且返回空列表 JSON
python -m pytest tests/test_filter_empty_query.py -q
```

【需开发】【需实测】

### 切片 C3：经验复用（同类问题拦截）

| 项 | 内容 |
|---|---|
| 目标 | 注入「空查询必须安全」已发布规则后，新开发若再引入缺陷，验证助手新检查拦截 |
