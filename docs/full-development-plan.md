# Full 详细开发计划

交付对象：Grok Bot 指挥官及开发团队。

计划性质：基于现有代码的增量开发方案，尚未实施。Lite、Team、Full 是长期并存、独立选择的三条产品线；本计划的阶段编号仅表示 Full 内部开发顺序。

代码审阅基线：`00aaf2f92652175325d6cc0802cab8ec26b0f543`。本次阅读了 kit 全部生产 Python 模块与测试、Demo 源码与测试、导入包、角色指令、Schema、演示脚本及相关文档；重新执行 kit 测试 72 项、Demo 测试 18 项，全部通过。这证明现有测试覆盖的行为通过，不代表 Full、真实多助手并发、三平台 OMB 导入或所有演示脚本已经验收。

## 一、目标与纠正

Full 的目标是实现参考图全部角色和工作链路，并使新人能够按照文档独立部署、配置必要凭据与权限、运行可追溯 Demo。

Nancy 已经在 Team 中，Matcha 也已经存在，不能写成 Full 新增角色。现有 Team 共 7 个角色：幕僚长、云端编程助手、验证助手、Nancy、Matcha、工程 bot ①、工程 bot ②。后两者当前为 stub，仅确认指派、记录占位状态。

Full 的角色增量是：

- 复用现有 7 个角色，并按 Full 职责增强。
- 将工程 bot ①②从 stub 升级为真实工程任务协调者。
- 新增工程 bot ③④。
- 新增 Dr. Eggbot、Tsuki、Potato、Crumb。
- 最终共 13 个逻辑助手角色；用户本人不计入助手数量。

定时任务、自动合并和技能/规则库是系统能力，不额外计算为助手。13 个角色不等于 13 个常驻模型进程；角色身份、权限、状态独立，执行按事件唤醒。

严格遵循图片的职责和流向。图片中 Nancy 与“只跟 Nancy 和幕僚长说话”标注为用户补充，本项目以用户提供的完整图片为产品规格，不把这些补充宣称为已核实的演讲原话。

## 二、真实代码基线与增量边界

| 能力 | 现有实现 | Full 工作 |
|---|---|---|
| Nancy | `team.py` 可读子任务状态、生成汇总、记录阻塞升级；导入包已有角色 | 复用并增强待办、日程、进度订阅、提醒、去重与权限边界 |
| Matcha | 创建 child task、向 A/B stub 指派、记录分配 | 增强为四工程协调、依赖管理、实际派发和失败重排 |
| 工程 A/B | 指令与 API 明确为 stub；可确认和回报备注 | 升级为真实拆解、交接、跟进；仍不写业务代码 |
| 开发助手 | 已有角色指令、任务协议、待验产物约定 | 接通真实编程执行器；名称含“云端”不证明当前已有云端执行集成 |
| 验证门 | 检查必做项执行标记、退出码、总结果及产物/验收 commit 匹配 | 增加独立执行器、逐轮逐检查绑定、证据来源校验 |
| 本地合并 | `merge/execute.py` 已实际执行本地 Git 合并；支持 confirm、auto | 加强并发锁、完整验收复核、目标基线绑定、集成后行为检查 |
| 预算 | 尝试次数、时长、手工记录 token 和进入执行状态时检查 | 接入真实用量、运行期中止、并发预留、项目总额 |
| 恢复 | 保存阻塞和恢复点，可恢复任务状态 | 接通实际进程/远端运行恢复与重启对账 |
| 经验沉淀 | 已有候选、审核、发布和规则探针 | 扩为可验证、版本化、按任务适用范围加载的闭环 |
| 外围专项 | 尚无完整 Eggbot、Tsuki、Potato、Crumb 业务实现 | 新增对应角色与真实业务接口 |
| 外围监控 | 导入包 routines 为空 | 新增 Slack、X、邮件、Linear 接入与持久化调度 |

以下差距要先处理，不能被“测试已通过”掩盖：

1. `record_check` 接受调用方填入的执行信息，现有验证门不负责运行命令，也不证明日志真实存在。每条旧检查还缺少独立的验收轮次/commit 绑定。
2. `merge-precheck` 不等于完整验证门。集成分支已前进时，仅判断能否合并不足以证明验收仍有效；当前合并后检查主要为祖先关系和可选文件存在。
3. 合并幂等分支也必须重新核对有效验收和集成后结果，不能只因产物已在目标分支就宣布任务完成。
4. Team 角色限制只覆盖部分 Team API；通用任务命令中的 actor 是调用参数，尚非可信身份边界。只靠提示词和敏感词扫描不能保证权限隔离。
5. JSON 状态直接写文件，缺少跨进程事务或锁；`worktree.path` 字段本身不会创建真实 Git worktree。
6. Nancy 当前把“验证通过、待合并、已完成”归入同一 doneish 指标；重复汇总可能重复升级同一阻塞。Full 应明确分别展示这些状态。
7. Schema 与运行时扩展字段需统一；部分旧脚本使用占位 commit 或依赖既有运行目录，不应直接当作干净环境验收入口。
8. 当前预算与恢复主要属于协议层能力，不能表述为已具备运行中自动停机、真实 token 计费和真实进程恢复。

## 三、三条平行产品线

| 产品线 | 独立入口 | 角色与定位 |
|---|---|---|
| Lite | 现有 Lite 导入包 | 3 角色，最小开发—验证—合并闭环 |
| Team | 现有 Team 导入包 | 7 角色，保留当前能力边界，独立维护 |
| Full | 新建独立 Full 导入包 | 13 角色，完整工程链路与外围业务 |

约束如下：

- 用户可直接选择任意一条已发布产品线，无需先装 Lite 或 Team。
- Full 包必须自带全部 13 个角色与完整指令，不要求先导入 Team 补 Nancy。
- 三线共享 kit 核心，通过显式 profile/capability 启用功能；运行目录、身份命名空间、端口、凭据引用、预算、任务与规则空间相互隔离。
- 不通过全局放开 `eng_stub` 权限来实现 Full；Team 默认行为和测试保持兼容。
- 新目录与展示名使用 `full`、`Lauren Full` 等稳定名称，不使用 `full-v...`。协议版本、发行标签等技术版本仍可正常存在。
- 跨线迁移是显式导入/导出能力，不是部署前提。运行中的任务不静默换线；降级前处理无法映射的任务和角色。
- README 并列展示三条入口、支持状态与能力差异。Full 开发期间标记“未发布”，不能把规划入口写成可用功能。

部署规格与服务连接组合分开配置：部署规格仍是 Lite / Team / Full；连接组合可选国内服务、国际服务或自定义混合。连接组合不是新的产品线，也不自动代表数据存储或处理地域。国内接口先在 Full 定义，通过兼容测试后允许其他产品线按需复用，不强制 Lite/Team 安装外围依赖。

## 四、角色及图中链路

### 4.1 十三个角色

| 角色 | 来源 | Full 职责与禁止事项 |
|---|---|---|
| 幕僚长 | 复用 | 收目标、定范围、冻结验收、分派 Matcha/专项 bot、处理升级、请求策略内合并；不写业务代码 |
| Nancy | 复用增强 | 日常待办、日程、进度正本、提醒、汇报；与幕僚长同步，不签发技术验收、不改预算、不合并 |
| Matcha | 复用增强 | 管四个工程 bot、分配工作流、协调依赖与冲突；不写代码、不宣布通过 |
| 工程 bot ①② | stub 升级 | 拆成可执行开发包、调用编程助手、跟进验证修复；不亲自写代码 |
| 工程 bot ③④ | 新增 | 与①②同一协议与权限；按任务分工，避免固定闲置岗位 |
| 云端编程助手 | 复用并接执行器 | 在隔离工作区真正实现、自检、提交精确版本；不写独立验收结论、不合并 |
| 验证助手 | 复用增强 | 在指定版本实际运行应用与检查、保留证据；失败退修，不顺手改业务代码 |
| Dr. Eggbot | 新增 | 定期审查所有 bot 的质量、成本、阻塞与权限异常，给幕僚长建议；不直接改策略或发布规则 |
| Tsuki | 新增 | 执行幕僚长交办的个人事务；Nancy 维护日程与跟踪，Tsuki 负责具体专项办理，二者不重复维护进度正本 |
| Potato | 新增 | 分析 X 内容、筛选相关信息并给出带来源的结构化结果；不擅自发布内容 |
| Crumb | 新增 | 扫描受控目录、提出并执行策略内清理、提供回收记录；不清理任务证据和活跃工作区 |

### 4.2 工程主链路

```text
用户 → 幕僚长 → Matcha → 工程 bot ①/②/③/④
                              ↓ 拆好的开发包
                         云端编程助手
                              ↓ 精确 commit + 自检
                           验证助手
                    ┌─────────┴──────────┐
                    ↓ 通过               ↓ 失败
              策略校验与本地合并     失败证据 + 候选规则
                    ↓                    ↓
              集成后检查与归档      工程 bot 安排修复
                    ↓                    ↓
              Nancy 汇报进度       云端编程助手重新提交
```

失败不会自动变成生效规则。候选须经有效性与误伤检查后发布，再分发至四工程 bot 和后续开发包；“不再犯”应作为可验证的预防目标，不能保证模型永不犯错。

自动合并走已有 auto 能力的增强路径，不再重复造合并器。用户预先配置允许的仓库、目标分支与自动合并策略后，通过程序门禁自动执行；confirm 模式继续可选。第一交付目标为受控 Demo 本地集成分支，远程推送/PR 合并是独立、明确配置的扩展。

### 4.3 外围与汇报链路

```text
用户 ↔ Nancy：日常、待办、日程、进度
用户 ↔ 幕僚长：方向、范围、重大决定
Nancy ↔ 幕僚长：项目进度与待办同步
工程线与专项 bot → Nancy：结构化进度回报
Slack / X / 邮件 / Linear → 定时任务 → 幕僚长
幕僚长 → Tsuki / Potato / Crumb：专项委派
Dr. Eggbot → 幕僚长：审查与改进建议
```

外层 X 接入负责增量采集与事件化，Potato 负责内容分析，使用同一来源 ID 去重。进度回报不构成额外指挥通道，Nancy 不绕过幕僚长派工程任务。外部内容作为任务数据，不作为可覆盖系统权限和验收标准的指令。

## 五、核心协议与运行架构

### 5.1 复用协议，补齐运行字段

保留现有 task 协议和状态机，按兼容策略演进，不另建一套彼此无法互认的 Full 协议。新增字段先在权威 Schema 定义，再同步模型、CLI、导入说明与测试；明确旧实例读取和迁移策略。

需覆盖的字段组：

- 身份：profile、project_id、run_id、task_id、parent_id、actor_id。
- 调度：依赖、受派工程 bot、执行器实例、状态修订号、幂等键、取消标记。
- 范围：目标、输入文件/来源、输出格式、验收标准、截止点、权限与非目标。
- 版本：代码仓库、真实 worktree、源 commit、集成基线 commit、验收轮次、实际集成 commit。
- 执行：命令、cwd、开始/结束时间、退出码、执行器回执、日志摘要。
- 用量：请求 ID、模型、已报告输入/输出 token、估算与实测标记、预算预留/结算。
- 规则：本轮加载规则的 ID、版本、适用范围、有效性证据。

每一条验收检查必须绑定本轮 run/attempt、待验 SHA 和验收定义版本。提交新版本、改变必做项或改变相关环境后，旧通过记录不能自动复用。

### 5.2 状态与并发

工程主状态继续使用现有中文状态；调度排队、依赖等待和执行租约等作为清晰的补充状态/字段，不将“被指派”视为“已执行”。

实现原子写入与跨进程锁，或采用具备事务能力的存储后端；对同一任务更新进行修订号校验。共享集成分支采用串行队列和仓库级锁，业务文件并行修改在独立真实 worktree 中进行。

Full 固定有四个工程协调角色，实际编程执行并发可配，初始建议上限 2。验收必须展示四个角色均能接受真实任务，以及至少两个执行任务有可核实的时间重叠；合并串行。

### 5.3 可执行的权限边界

统一在可信运行入口检查角色、profile、任务归属和操作权限。所有改变产物、验收、预算、规则与合并结果的通用命令都纳入检查，不能只管 Team API。

模型只能请求操作，程序负责策略校验与执行。编程执行器不得使用验证器与合并器的写入凭据；Nancy、Matcha、工程 bot 不能填写验收通过。任务 ID、日志路径和清理路径必须验证归属与目录范围。

此边界用于限制代理及工具调用，不宣称能防止拥有本机管理员权限的人篡改整个运行环境。

### 5.4 本土化原则与首发边界

保留原图角色、工程链路和 Slack/X/邮件/Linear 对应能力，在外围引入可替换适配器。用户换模型或消息平台时，不需要更改角色提示词、状态机、验证门和合并策略。

本计划仅预留国内对接接口，不将飞书、钉钉、企业微信等全部列为本轮必须完成的真实接入。首发边界如下：

| 范围 | Full 首发交付要求 | 后续扩展边界 |
|---|---|---|
| 通用接口底座 | 接口契约、注册机制、能力发现、错误规范、配置校验、契约测试、参考适配器 | 所有提供方共用，不按厂商复制工作流 |
| 国内模型入口 | 自定义服务地址/模型/凭据接口；选定一个目标国内服务完成实际工具链验收 | 其他模型只标候选或契约已适配，不承诺全兼容 |
| 国内消息入口 | 飞书、钉钉、企业微信的适配器挂载位和能力声明；本地收件/通知参考实现 | 启动实现时选一个平台作为下一真实接入，不默认三个都做 |
| 日历与待办 | Nancy 本地存储实现；外部日历、待办、任务平台统一契约 | 国内外提供方经同一契约接入；已有 F4 外部提供方目标仍保留 |
| 国内信息源 | 官方 API、RSS、授权 Webhook、用户文件导入接口及离线样例 | 具体站点逐个评估可用接口与权限，不预设任意抓取能力 |
| 代码托管与执行器 | 本地 Git 可独立工作；远程托管、编程执行器可替换接口 | 国内托管平台的 issue/PR 等能力另行实装和验收 |

原图四来源的发布要求保留。国内服务组合可以先单独验收并标注其能力范围；缺少原图连接实测时，不能因此宣称“全图全部接入完成”。预留接口必须交付可执行的契约测试和挂载样例，不能只留下空类或文档标题。

### 5.5 接口分层与扩展点

以下名称是拟议契约，不表示仓库已经存在这些模块；F0/F1 先与现有结构对齐，F2 建立骨架。

| 接口 | 关键操作/数据 | 国内预留方向 |
|---|---|---|
| ModelProvider | 能力发现、请求、流式事件、工具请求/结果、结构化输出、用量、取消 | 可配置服务地址的兼容协议、提供方原生协议、本地推理网关 |
| AgentExecutor | 启动、查询、取消、恢复/对账、工作区与产物回执 | OMB 与不同编程执行工具；不将模型 API 当作完整编程执行器 |
| MessageChannel | 接收事件、发送通知、回复会话、关联外部身份 | 飞书、钉钉、企业微信；只支持通知 Webhook 的连接不能伪装成双向入口 |
| SourceConnector | 增量读取/订阅、分页游标、事件归一化、来源引用 | 邮件、企业工作台、授权信息源、RSS、文件；保留 Slack/X/Linear 实现 |
| CalendarProvider | 查询、创建、更新、取消日程、变更游标、版本冲突 | 国内工作台日历和标准日历连接，具体能力按提供方声明 |
| TodoProvider | 待办查询/创建/更新/完成、外部状态映射、版本 | Nancy 本地待办及国内任务协作系统 |
| RepositoryProvider | 克隆/获取引用、可选 issue/PR、远程状态 | 本地 Git、可配置远程主机；高级能力不依赖某一家托管服务 |
| CredentialStore | 按连接取凭据、刷新、撤销、健康状态 | 环境变量引用、系统凭据库或部署环境提供的保密存储 |

消息入口负责用户交互，来源连接负责采集；同一平台可实现两个接口，但只能向核心投递一份具有稳定 ID 的业务事件。Potato 消费信息源的标准数据，Nancy 消费消息/日历/待办契约，不直接引用厂商 SDK。

建议采用内置适配器注册表与可选依赖分组，先保持简单；不为预留接口提前建立独立微服务体系。扩展点不得自动下载并执行未知插件。

### 5.6 统一事件、能力声明与身份

所有接入事件至少包含：事件协议版本、event_id、connection_id、外部事件 ID、来源类型、租户/工作区、会话、外部操作者、发生时间、接收时间、正文或受控附件引用、来源链接、内容摘要、可信等级与 trace_id。

时间落盘使用带时区的时间戳，内部比较统一基准；展示采用连接/用户设置，国内预设为 Asia/Shanghai。中文自然语言日期由 Nancy 转为明确日期并回显；节假日与工作日规则通过可替换日历数据提供，记录来源和适用年份，不硬编码每年放假安排。

连接必须声明支持哪些动作，例如 inbound、outbound、reply、calendar_write、todo_write、tool_calls、structured_output、usage、cancel、resume。配置校验与界面只开放已声明且通过探测的动作；不支持时返回明确结果，禁止静默假成功或自动换到另一个服务。

外部用户先映射到本地 actor 与项目权限。不能仅凭显示昵称认定为主人或幕僚长；群成员不自动拥有改预算、合并或触发清理的权限。通知卡片按钮如涉及操作，绑定操作者、任务修订号、有效期与一次性标识，并由程序重新校验策略。

Webhook 由适配器按提供方规则校验身份、签名、时间和防重放条件，成功持久化事件后再确认接收；轮询连接持久化游标。统一按至少一次投递设计，通过连接 ID、外部事件 ID 和操作幂等键去重，区分重试与用户有意重复提交。

统一错误至少区分：未配置、能力不支持、认证失效、权限不足、限流、网络失败、内容不可用、版本冲突、执行结果未知。可重试错误采用有上限的退避；永久错误转阻塞并由 Nancy 汇报，不循环消耗 token。

### 5.7 模型与执行器适配要求

“兼容某种 HTTP 协议”只代表传输入口可用，不代表能跑完整工程链路。对每个实际支持的模型/引擎组合，建立能力矩阵并实测：

- 中文需求与路径处理、流式响应、工具参数与结果关联、多个连续工具调用。
- 结构化输出的解析与验证、上下文限制、超时与取消、错误恢复。
- 文件读写/终端执行由谁提供、权限如何约束、产物如何绑定 Git SHA。
- 提供方实际返回的 usage、费用币种和估算标记；费用缺数据时不显示虚构金额。
- 开发与验证的会话、工作区、工具权限分离；允许同一模型提供方，但不能让开发者自述替代独立验证。

模型调用若由 OMB/编程工具管理，适配它们真实暴露的设置和回执，不在 kit 里再暗建一套模型调用绕过引擎。只有确有直接模型调用的模块才使用 ModelProvider。提供方不支持工具调用或取消时，按角色要求禁用相关任务或标受限，不能仅因普通问答成功就判“模型已支持”。

模型路由、备用提供方、代理和端点均由用户显式配置。失败不会自动向另一个地区或服务转发代码、聊天与附件；配置修改适用于后续调用，并记录任务使用的实际连接。

### 5.8 配置、中文体验与部署诊断

拟议配置示意，仅用于说明契约；不表示当前存在对应配置文件或命令：

```yaml
profile: full
connection_preset: domestic
locale: zh-CN
timezone: Asia/Shanghai
connections:
  model_primary:
    adapter: configurable_model_api
    enabled: true
    endpoint_env: LAUREN_MODEL_ENDPOINT
    model_env: LAUREN_MODEL_NAME
    credential_ref: env:LAUREN_MODEL_API_KEY
  domestic_messages:
    adapter: feishu             # 预留标识；安装并验收相应适配器后才能启用
    enabled: false
    credential_ref: env:LAUREN_MESSAGE_CREDENTIAL
  personal_calendar:
    adapter: local_calendar
    enabled: true
  personal_todos:
    adapter: local_todos
    enabled: true
```

国内/国际预设只提供连接模板，不自动创建账号、购买服务、授予权限或保证数据地域。默认模板不附带真实 Key、租户标识、代理地址和私人路径；未安装适配器若 enabled=true，启动时明确报错。

增加连接诊断入口，逐项显示依赖、DNS/TLS/端点连通、凭据、授权范围、能力探测、最后成功同步与错误原因；诊断日志不得打印完整凭据或消息正文。用户可只诊断指定连接，无需开全套外围服务。

三平台安装支持可配置依赖索引、网络代理和离线依赖包说明；不覆盖用户全局 Git/Python 配置，不关闭证书校验。针对 Windows 提供原生命令或跨平台 Python 入口；中文路径、长文件名、UTF-8、CRLF、时区和通知文本纳入验证。

### 5.9 数据流向、双向同步与业务边界

每个连接声明读取/写入范围、数据去向、保存位置和日志保留策略。提供“禁止外发”“仅允许指定端点”“发送前按策略脱敏”等可执行设置；脱敏不足以满足任务要求时阻塞，不静默发送原文。名称叫“国内服务”不构成数据不出境的证明。

附件先验证类型、大小、归属和受控路径，再传给任务；消息、网页、文件中的内容按数据处理，不能修改工具权限。引用来源保留采集时间与外部 ID，转载、删除或不可访问时如实记录。

Nancy 的项目执行状态以 kit 为准；个人待办/日程每类配置一个权威来源，其他连接保存外部 ID 与版本映射。不得让 Nancy、Tsuki 和外部日历各自覆盖同一份事实。用户在外部改日程时按版本检测冲突；发送超时而结果未知时先查询对账，不能盲目重复创建。

国内公开信息源接入优先使用可用的官方接口、授权连接、RSS 或用户导入。若某站点无所需接口，标明未支持，保留人工导入；不把绕过登录、验证码或抓取限制作为默认实现。个人微信与企业微信是不同目标，不因预留企业微信接口就宣称可自动操作个人微信。

## 六、Full 内部开发顺序与退出条件

### F0：基线对齐与兼容保护

工作：建立“已有/增强/新增”清单；统一 Schema 与实际字段；修复假 commit、依赖旧目录的演示入口；调整过时指令和文档。保留历史证据，不覆盖旧运行结果。

交付：Full 架构与能力表、协议变更说明、干净环境可运行的基线验证入口；确定国内模型目标、消息候选、外部日历/待办目标与其认证、网络、权限要求。具体提供方实现前核对官方接口文档，记录核对日期与限制，不依据本计划中的候选名称推定其 API 能力。

退出条件：当前 72 + 18 项测试保持通过，新增契约一致性检查通过；Lite 与 Team 独立导入结构和原有默认行为不回归；旧脚本逐项标明“可运行、需迁移、历史归档”。

### F1：独立 Full profile 与 13 角色导入骨架

工作：增加 Full 配置、命名空间、13 角色完整指令与独立导入包；复用 Nancy 和 Matcha 定义但使用 Full 指令；为工程 A/B 增加 Full 能力，不改变 Team stub 默认语义。定义服务连接配置、适配器能力清单和国内/国际/混合模板，分别标明已支持与预留项。

建议目录：`lauren-omb-pack/full/`，入口 `lauren-full.botmrr.md`，同时维护受支持的兼容导入格式。运行数据根目录由 profile 显式配置，不依赖用户私人路径。

退出条件：全新 OMB 环境只导入 Full 即得到 13 个角色；各角色职责一致；Lite/Team/Full 同机部署身份与数据不串线。此时只称“导入与配置完成”，不称业务完成。

### F2：可信执行、证据与共享底座加固

工作：实现真实 worktree 管理、原子状态更新、可信操作入口、独立验收执行器、完整合并门禁、进程级预算与恢复接口；交付适配器注册、凭据引用、事件持久化、去重、错误与契约测试底座及本地参考实现。

验收执行器必须实际执行全部必做项，保存 stdout/stderr、退出码、时间和版本。程序从执行回执生成报告，不允许拿普通对话中的 JSON 作为可信通过证明。现有人工记录命令可保留诊断用途，但不能直接获得 Full 自动合并资格。

合并前再次运行完整验证门，解析真实 Git SHA；检查集成基线变化。集成提交须实际执行集成检查；若不通过，记录失败并在隔离的集成事务中中止或撤回，不能仍标已完成。幂等重试也核对同一产物、目标和有效报告。

退出条件：伪造报告、旧轮次检查、缺日志、非零退出码、变更 commit、过期集成基线、角色越权、并发覆盖、重复合并和集成后失败均有有效拦截测试。

### F3：Matcha + 四工程 bot + 真实编程执行器

工作：把记录型指派接到实际 OMB 委派/执行器适配层；四个工程 bot 负责拆解与跟进；编程助手在隔离会话执行代码工作。若多个执行实例并发，共享同一个逻辑角色定义，但分别记录实例和工作区。

先验证目标 OMB 环境真实支持的委派、运行状态查询、取消与重连方式，再固定适配器契约。不能把单个助手轮流扮演 13 个角色算作 Full 验收。

增加子任务依赖、归属、失败重排和取消传播。Matcha 跟踪工程状态，工程 bot 交付开发包，编程助手提交待验版本；未接通真实云端提供方时明确标记本地执行器，不以显示名称冒充云端交付。

退出条件：四个工程 bot 各完成至少一次真实交接；至少两任务实际并发、独立产物、独立验收；依赖未满足不得启动；冲突进入串行集成处理；失败只重跑受影响部分。选定国内模型/引擎组合完成真实编程—工具调用—独立验证链路，记录其限制与真实用量可用性。

### F4：复用并增强 Nancy 与汇报链路

工作：复用 `team-status`、`team-summarize` 的数据能力；将 verified、pending_merge、completed 分开统计；阻塞按任务/原因/状态变化去重；已解除阻塞不持续告警；多次汇总不重复升级。

增加待办、截止时间、提醒、项目进度订阅与日程适配器。先完成本地持久化待办和日程，再接一个真实外部日历/待办提供方，具体提供方在开工时固定。用户能看到读写范围和最后同步状态。

Nancy 接收工程及专项 bot 事件，向用户按需汇总；紧急阻塞即时提示，普通变化合并报告。对外日程变更按用户配置的授权策略执行。日历/待办使用统一适配器，不将厂商字段写入 Nancy 核心；中文时间回显、时区、幂等和双向冲突处理一起验收。

退出条件：真实任务从启动、受阻、恢复、待合并到完成均可追踪；无重复阻塞提醒；“待合并”不会被报告为“完成”；同一待办不因双向同步重复创建；用户无需遍历群聊了解项目。

### F5：外围定时监控与三个专项 bot

工作：实现 Slack、X、邮件、Linear 四种来源适配器，共用增量游标、去重、重试、限流和脱敏事件协议；定时任务发现问题后交幕僚长决定是否立项。重启从持久化游标继续，不全量重复抓取。国内消息平台、国内任务系统和信息源按第五节的扩展点接入，首发完成接口与契约测试；真实厂商适配另列任务和验收，不混入原图四来源的完成统计。

为 Tsuki 实现具体个人事务工作流及回执；为 Potato 实现有来源链接、采集时间和相关性说明的 X 信息分析；为 Crumb 实现目录白名单、预览、清理策略、回收或恢复记录，并保护活跃 worktree、证据、凭据和版本库。

退出条件：四来源分别完成契约测试与真实账号连通验收；三专项 bot 各有真实任务。缺凭据时显示“未配置/未实测”，录制数据或 mock 不能计作真实连接通过。外部内容无法改写系统策略。

### F6：Dr. Eggbot 与经验反馈闭环

工作：新增 Eggbot 对所有角色及执行器的质量、成本、失败率、阻塞和权限请求审查，向幕僚长提交带证据建议。审查不直接触发加预算、改权限或发布规则。

复用现有 lessons 候选/审核/发布机制，补上实际有效性探针、适用范围、版本、停用回滚、运行时加载回执。修复规则文件与 store 内容可能不一致的问题，避免以“文件存在”当作规则正确应用。

退出条件：一个真实失败产生候选规则；规则能在已知错误版本识别问题，在正确版本不误伤；审核后版本化发布；四工程 bot 的后续开发包均记录加载了该规则；再次触发相同问题时可观测到预防或拦截。

### F7：全图验收与独立发布

工作：从干净环境执行完整 Full 场景，完成三平台部署和 OMB 导入验收、预算/恢复故障演练、证据脱敏、文档、发行与回归。

退出条件：第八节全部发布门槛满足。任一来源或平台未实测时，明确发布为受限预览及其缺口，不称“完整复现、三平台即用”。

依赖顺序：F0 → F1 → F2 → F3；F4 的基础汇报可与 F3 同步；F5 接入必须使用 F2 的可信运行接口；F6 基于实际运行记录与 F2 的验证能力；F7 最后统一验收。

## 七、预算、重启和异常处理

1. 角色按需唤醒。普通状态读取、汇总计数、Git 门禁和调度尽量由程序完成，不为每次心跳调用模型。
2. 设置任务、执行器和 Full 项目级预算，以及最大并发、最大修复轮次、最大运行时长。调度前预留预算，运行后结算，防止并发任务分别通过却总额超限。
3. 优先记录提供方真实 usage；不可获得时明确估算，不伪造精确账单。硬 token 限额需结合提供方单次输出上限；不支持精确中止时标出限制，并通过调用额度、时长和停止新派发控制风险。
4. 运行中达到可监测阈值时取消或停止后续调用，保存受阻点；Nancy 汇报，幕僚长不得自行抬限。
5. 重启后对账任务、租约、进程、远端 run、worktree、commit 和合并报告；先确认上次执行结果，再决定恢复、重试或人工处理。
6. 外部创建待办、日程、写入服务以及合并等操作使用幂等键；不宣称跨外部系统天然具备 exactly-once 保证。
7. 日志不足或无法判定执行结果时保持受阻，不凭历史聊天记录继续宣告成功。

## 八、发布验收清单

### 8.1 主线场景

- 干净部署：不装 Lite/Team，单独导入 Full，配置模型与必要权限，完成环境诊断。
- 四工程协调：四个工程 bot 均真实参与；至少两任务执行时间重叠；代码全部由编程执行器产生。
- 正常闭环：用户需求 → 幕僚长 → Matcha → 工程 bot → 编程助手 → 独立验证 → 自动本地合并 → 集成检查 → Nancy 汇报完成。
- 失败闭环：首次验收失败 → 失败证据 → 工程 bot 调度修复 → 新 commit 重新验收；失败记录保留；规则经测试、审核和发布后反馈工程线。
- 外围闭环：四来源事件至少分别触发一次；幕僚长完成去重/分派；三个专项 bot 有实际业务回执。
- 审查闭环：Eggbot 定期审查并给出可追溯建议；幕僚长处理建议；无自动扩大权限。

### 8.2 故障与反例

- 缺检查、伪造退出码、缺证据、旧验收轮次、旧 commit、集成基线变动均不能自动合并。
- 依赖失败、重复事件、同任务双派发、并发写状态、文件冲突、合并后检查失败有确定结果。
- 模型失败、限流、网络中断、执行器进程被杀、应用重启、预算耗尽均能记录并恢复或安全受阻。
- Nancy/Matcha/工程 bot 不能越权改验收与合并结果；外部消息不能提升权限。
- Lite/Team 原有能力与导入包回归通过，三线同时运行不混数据、不互相消费预算。

### 8.3 三平台验收

macOS、Windows、Linux 均为发布支持目标。Python 与 Git 核心使用跨平台实现；不能将现有 Bash 脚本直接当作 Windows 支持方案。

每个平台分别验证安装、路径含中文/空格、依赖诊断、OMB 导入、真实委派、应用运行、证据、Git worktree/合并、取消、预算与重启恢复。记录实际系统、OMB、模型引擎版本和证据。

先核实目标 OMB 发行版在三平台的可用方式。某平台只有 CLI 或替代运行方式时，在文档明确，不把 CLI 通过写成 OMB GUI 已通过。

### 8.4 证据要求

每次验收生成独立 run，归档环境、profile、角色/执行器、来源事件、任务依赖、输入输出、真实命令、退出码、时间、代码与基线 SHA、验收轮次、集成结果、模型用量及规则版本。

运行证据默认不提交公开仓库；只发布脱敏样例。不得包含个人本地路径、公司目录、账号标识、token、私信原文、个人日程或未授权业务数据。自动扫描与人工复查共同作为发布检查。

### 8.5 本土化与接口预留验收

- 配置正交：切换国内/国际/混合连接组合不改变 Full 角色数与工程门禁；Lite/Team 不被迫引入未使用的厂商依赖。
- 国内模型：至少一个选定组合完成真实工具调用、编程产物、独立验证及错误处理；不能仅用聊天成功代替。
- 可插拔：本地参考适配器能通过公共契约接入；更换为测试适配器无需修改 Nancy、Potato、幕僚长等核心业务。
- 预留状态：飞书/钉钉/企业微信等候选逐项标为“仅预留、契约测试通过、已实现、已实测”；未启用项不阻止无关任务，误启用项明确报错。
- 事件可靠性：重复投递、分页重启、游标丢失、限流、凭据过期、越权消息和延迟通知有确定结果，不重复派发或无限调用模型。
- 日历/待办：同一请求重试不重复创建；外部修改产生版本冲突；北京时间与中文日期明确；状态变化不会反复同步成新事件。
- 消息权限：陌生用户、同名用户、过期按钮与重放事件不能触发合并、抬预算、清理；发送通知成功与业务执行成功分别记录。
- 网络与数据：端点不可达时不静默切服务；代理/镜像配置不改全局设置；Key 不出现在日志；禁止外发策略能实际阻止网络请求。
- 来源标记：本土替代场景与原图场景分别出报告。预留国内接口通过不计作国内厂商真实接入完成，也不替代原图四来源验收。

## 十、指挥官执行与汇报口径

开工先完成 F0 的基线与契约对齐，再按依赖顺序派发。每个开发任务固定填写：目标、基线、可改范围、输入、输出、真实验收命令、失败条件、证据位置、预算、截止点和回滚方式。

每阶段报告分别列出：已实现、已通过自动测试、已在 OMB 实测、未实施、受阻及下一验收点。不得用角色已显示、已写任务 JSON、已填通过字段或测试数量代替真实业务完成。

本计划的关键边界是：Nancy 与 Matcha 复用增强；工程 A/B 占位升级；新增 C/D 与四专项角色；验证、合并、预算、恢复、经验库在现有实现上加固接线。Full 与 Lite、Team 独立部署，且共享核心改动必须保持兼容。

国内适配通过连接配置和外围接口扩展；不新增第四条产品线、不改变原图分工，也不把“预留接口”报为“厂商对接完成”。每个厂商实现任务都需引用当时核对的官方接口、最小权限、认证方式、可用能力和真实验收证据。
